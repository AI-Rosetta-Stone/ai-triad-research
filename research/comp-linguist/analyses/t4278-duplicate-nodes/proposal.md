## What the per-entry inspection found (playbook check A)

- **Eight duplicated labels across all three POV files.** They're exact copies, near-exact copies, or the

- **The copies have drifted since duplication.** Each one picked up its own `debate_refs`,

- **The corpus has no deprecation field.** No node in any POV file carries a status, deprecated,
  superseded or merged field. So "deprecated" exists only as prose.

## Options

**A. Merge: delete the retired nodes, add an alias map, rewrite live references.**
- Retired IDs disappear from the POV file.
- A new `id-aliases.json` maps each retired ID to its survivor.
- Every reader (the TS loader, the editor, PowerShell) has to resolve aliases, or historical debates
  dangle.
- The live references get rewritten, with the reference lists merged.
- **Cost:** a new file type plus a resolver in three code stacks, a big diff, and retired IDs are hard to
  undo. **A shape change, so the t/3361 Second Opinion applies.**

**B. Supersede in place (recommended).**
- Each retired node stays in the POV file, and gains `superseded_by: "<survivor id>"`.
- Its references are **added to the survivor's** reference lists, with duplicates removed. The retired
  node keeps its own lists unchanged, so history stays intact.
- **Readers that choose nodes skip superseded ones.** That covers grounding, relevance selection and the
  editor's default lists; t/4352's label dedupe is the stopgap until then. Readers that resolve an ID
  still find the node, so every historical reference resolves.
- **Cost:** one additive optional node field, plus "skip if superseded" in the selection paths. **Undo it
  by deleting the field.**
- **Tier: T1** under the Schema-of-Record rule. It's an addition-only normative field in `node_fields`,
  with CL approval plus Quality. The data write is still a corpus write, so it goes to the PI.

**Why B:** it fixes what users see (duplicates in selection), keeps every historical reference
resolvable, avoids rewriting hundreds of records, and is undone by removing one field. A gives a cleaner
corpus at the price of retiring IDs and a resolver in three codebases. Retiring IDs is still possible
later on top of B.
